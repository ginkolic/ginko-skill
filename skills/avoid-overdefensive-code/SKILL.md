# 避免过度防御编程

目标：写出**信任内部契约、在边界校验、出错即失败**的代码。防御性代码不是免费的：它掩盖 bug、制造死分支、让读者误以为某种情况真的会发生。

## 核心原则

1. **只在信任边界校验**。外部输入（用户输入、HTTP 请求、文件、环境变量、第三方 API 响应、反序列化数据）要校验；内部函数之间的调用信任类型和调用方契约。
2. **Fail fast，不要静默兜底**。出现"不可能的状态"时让它报错，而不是返回 `None`、空列表、默认值或打一行日志继续跑。
3. **只捕获你能处理的异常**。捕获异常的前提是：你知道具体是哪种异常，并且有明确的恢复动作（重试、换路径、转成对用户有意义的错误）。否则让它向上抛。
4. **不为想象中的需求写代码**。不加没人要求的配置项、开关、回退分支、兼容旧版本的逻辑。
5. **相信类型系统和已有校验**。上游已经保证非空/已校验/已规范化的值，下游不再重复检查。

## 禁止模式（除非满足"例外"条件）

| 模式 | 问题 | 替代做法 |
| --- | --- | --- |
| `try: ... except Exception: pass / log` | 吞掉 bug，现场丢失 | 删掉 try，或只捕获具体异常并给出恢复动作 |
| 每个函数开头 `if x is None: return` | 把调用方的 bug 变成静默的空结果 | 类型声明为非可选；真可能为空才处理 |
| 对内部参数 `isinstance` / `typeof` 检查 | 重复类型系统的工作 | 用类型注解；边界处统一校验 |
| `getattr(obj, "x", None)`、`obj?.a?.b?.c` 访问已知结构 | 掩盖结构错误 | 直接访问；结构不确定时在边界用 schema 解析 |
| `dict.get(key, default)` 读取必有的 key | 拼错 key 也不会报错 | 用 `dict[key]` |
| 失败后返回 `None` / `[]` / `{}` / `-1` 当兜底 | 调用方无法区分"空"和"出错" | 抛异常，或返回显式的 Result 类型 |
| 重复的输入校验（调用链每层都校验一遍） | 噪音、逻辑分散 | 在入口校验一次，之后传递已校验的值 |
| 为"可能将来需要"加参数、开关、fallback | 增加分支和测试负担 | 等真正需要时再加 |
| 防御性 `copy.deepcopy` / 克隆 | 无谓开销 | 只在确实存在共享可变状态风险时复制 |
| 注释写"以防万一"、"for safety"、"just in case" | 信号：这段代码没有真实依据 | 说出具体场景，说不出就删掉 |

## 例外：这些地方应该防御

- 系统边界：解析外部输入、网络/磁盘 I/O、子进程、第三方 SDK 调用。
- 公共库/对外 API 的入口参数。
- 有明确恢复策略的可预期失败：网络超时重试、文件不存在时创建、用户输入格式错误时提示。
- 资源清理：`finally` / `with` / `defer` 确保释放。
- 安全相关：鉴权、权限检查、注入防护——永远不省略。

## 写完代码后的自检

对每一处 `try/except`、`if x is None`、类型检查、默认值、fallback 问自己：

1. **这个情况在什么具体输入下会发生？** 说不出来 → 删除。
2. **如果真的发生了，静默处理还是报错更有用？** 大多数时候是报错。
3. **上游是否已经保证了这一点？** 是 → 删除。
4. **这是边界还是内部？** 内部 → 倾向删除。

修改已有代码时：不主动删除原有的防御代码（可能有历史原因），但**不要新增**同类代码；如明显有害，在回复中指出而非直接改动。
